# Project prompts and replay specification

Use this file as the **only context** to recreate the Go backend boilerplate in a new repo. Replace the sample module path `library-management-system/backend` with `<your-repo>/backend` (or any `module` path you choose) and update all internal imports to match.

---

## User prompts (chronological)

### Prompt 1 — Go backend scaffold

Create a new Go project in a folder named `backend`. The backend is a Go server with these dependencies:

1. **go fiber** — routing  
2. **gorm** — database  
3. **godotenv** — environment variables  
4. **compiledaemon** — file watching and server restarts  

**Folders**

1. `controllers` — route handlers and business logic  
2. `helpers` — reusable helpers  
3. `initializers` — env loading, DB connection, etc., invoked from `main`  
4. `models` — data models  
5. `middlewares` — HTTP middlewares (with recommendations for a robust API)  

**Files**

1. `main.go` — routes, DB init, server start  

**Environments:** `development` and `production`, each with its own env file loaded when that mode runs.

**Database:** PostgreSQL.

---

### Prompt 2 — Documentation and simpler configuration

1. Record all prompts in a file in the project (`PROMPTS.md`).  
2. Avoid fallback-heavy configuration (`BACKEND_ROOT`, `APP_ENV`, many optional env knobs). Prefer a **simple, conservative** setup.

**What was implemented**

- **Removed:** `BACKEND_ROOT`, reading env from anywhere other than process CWD, `APP_ENV` and implicit default environment, dual DB config (`DATABASE_URL` *or* many `DB_*` fields), pool tuning via env, HTTP timeout via env, dev-time `CORS_ALLOW_ORIGINS` env.  
- **Kept:** Required CLI flag `-env`, single `DATABASE_URL` for Postgres, fixed connection pool in code, fixed 30s handler timeout, dev CORS `*` in code, production CORS from env only (required at startup).

---

### Prompt 3 — Committed env files

Create real `.env.development` and `.env.production` (not only `.example`) with everything `LoadEnv` needs. Stop gitignoring those files so **other developers get the same baseline**; document that production files should hold **placeholders** until deploy, not real secrets in public repos.

**What was implemented**

- Added committed `backend/.env.development` and `backend/.env.production`.  
- Removed those paths from `backend/.gitignore`.  
- Removed separate `.env.*.example` files (single source of truth).

## Replay checklist — recreate the backend from scratch

### 1. Layout

Create directory `backend/` with:

```text
backend/
  go.mod
  go.sum          # generated by go mod tidy
  main.go
  Makefile
  .gitignore
  .env.development
  .env.production
  controllers/
    health.go
  helpers/
    response.go
  initializers/
    env.go
    db.go
  middlewares/
    middlewares.go
  models/         # empty package directory for future models (optional .gitkeep)
```

---

### 2. Module and Go version

- `go 1.22` (or newer; keep consistent with your toolchain).  
- `module <parent>/backend` — set `<parent>` to match the repo (e.g. `library-management-system/backend`).

**Direct dependencies**

- `github.com/gofiber/fiber/v2`  
- `github.com/joho/godotenv`  
- `gorm.io/driver/postgres`  
- `gorm.io/gorm`  

Run `go mod tidy` after adding imports.

**CompileDaemon** is not a Go module dependency; install for local dev:

```bash
go install github.com/githubnemo/CompileDaemon@latest
```

---

### 3. Environment files (committed)

Files are loaded from the **current working directory** only: run commands from `backend/` so `.env.development` or `.env.production` resolves correctly.

| Variable | `.env.development` | `.env.production` |
|----------|--------------------|-------------------|
| `DATABASE_URL` | Required (Postgres URL, e.g. local) | Required (placeholder URL until real deploy) |
| `CORS_ALLOW_ORIGINS` | Omit (not read in dev) | **Required** — comma-separated origins; validated in `main` `init` |
| `SERVER_ADDR` | Optional; default `:3000` if unset | Optional; default `:8080` if unset |

**Development file:** document local Postgres and `go run . -env=development`.  
**Production file:** use obvious placeholders (`REPLACE_USER`, etc.) in `DATABASE_URL`; warn in comments not to commit real secrets to a public repo.

---

### 4. `initializers/env.go`

- Constants: `EnvDevelopment = "development"`, `EnvProduction = "production"` (must match env file suffixes).  
- `LoadEnv(environment string)`: `godotenv.Load(filepath.Join(os.Getwd(), ".env."+environment))`, log path on success.

---

### 5. `initializers/db.go`

- Export `var DB *gorm.DB`.  
- `ConnectDB(environment string)`: read **only** `DATABASE_URL`; error if empty.  
- `gorm.Open(postgres.Open(dsn), cfg)` with logger: **Info** in development, **Error** only in production.  
- **Fixed pool** (no env): `SetMaxOpenConns(25)`, `SetMaxIdleConns(5)`, `SetConnMaxLifetime(30 * time.Minute)`.

---

### 6. `middlewares/middlewares.go`

`Stack(environment string) []fiber.Handler` — order matters:

1. `recover.New()`  
2. `requestid.New` — header `X-Request-ID`, context key `requestid`  
3. **CORS** — if `development`: `AllowOrigins "*"`, `AllowCredentials false`. If production: `AllowOrigins` from `CORS_ALLOW_ORIGINS` env; `AllowCredentials` true when origins non-empty and not `*`. Same methods/headers for both (include `OPTIONS`, `Authorization`, `X-Request-ID`).  
4. `logger.New` with a one-line format including time, status, latency, IP, method, path, error.  
5. `timeout.NewWithContext` wrapping `c.Next()`, **30s** fixed deadline.

---

### 7. `controllers/health.go`

- `GET` handler returning JSON `{"status":"ok"}`.

---

### 8. `helpers/response.go`

- `JSONError(c, status, message)` → `{"error": message}`.

---

### 9. `main.go`

- **`init`:**  
  - `flag.String("env", "", ...)` then `flag.Parse()`.  
  - `runEnv` must be non-empty and exactly `development` or `production` (use initializer constants).  
  - `initializers.LoadEnv(runEnv)`.  
  - If production: `CORS_ALLOW_ORIGINS` must be non-empty after trim, else `log.Fatal`.  
  - `initializers.ConnectDB(runEnv)`.  
- **`main`:**  
  - `fiber.New` with `AppName` (e.g. project API name) and `ServerHeader: "Fiber"`.  
  - Register every handler from `middlewares.Stack(runEnv)`.  
  - Register `app.Get("/health", controllers.Health)`.  
  - Listen: `SERVER_ADDR` if set, else `:3000` (dev) or `:8080` (prod).  
  - Log environment and listen address.

Import paths must use the same module path as `go.mod`.

---

### 10. `Makefile`

- `dev`: `CompileDaemon` with `-build="go build -o tmp/main ."`, `-command="./tmp/main -env=development"`, watch Go and `.env` files under `backend/`.

- `run-dev`: `go run . -env=development`  
- `run-prod`: `go run . -env=production`  

Comment at top: install CompileDaemon via `go install github.com/githubnemo/CompileDaemon@latest`.

## Design summary (for the next project)

| Area | Choice |
|------|--------|
| Router | Fiber v2 |
| ORM | GORM + Postgres driver |
| Config | godotenv; one file per mode; CWD = `backend/` |
| Mode selection | **Only** `-env=development` or `-env=production` (required) |
| DB connection | Single `DATABASE_URL` |
| Dev vs prod | GORM log level; CORS (wildcard vs explicit origins); default listen port |
| Middleware | Recover, RequestID, CORS, Logger, Timeout(30s) |
| Dev UX | Makefile `make dev` + CompileDaemon with `-env=development` on the binary |

This is the full boilerplate contract implied by Prompts 1–3 and the code as it exists in this repository.
